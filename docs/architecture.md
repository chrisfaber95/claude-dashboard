# Claude Dashboard: architecture and reference

Reference sections moved out of `CLAUDE.md` (which links here) so they load only when needed.

## Layout

- `src/server/`: Node 24 runs these `.ts` files directly (native type stripping, no compile step, no runtime dependencies)
  - `config.ts`: paths, ports, env overrides, small helpers
  - `transcripts/transcripts.ts`: incremental JSONL scanner (16 MB chunks) and all in-memory aggregates (tokens, messages, rate-limit hits, session → transcript index, subagent index); `buildSubagents()` filters live subagents; `subagentPaths` maps agent id to transcript path
  - `features/limits/limits.ts`: live usage API poll with fallback to the `.claude.json` cache
  - `transcripts/state.ts`: builds the `DashboardState` (live sessions, projects, subagents of live sessions, git info, CLI trust, feature flags, `team`)
  - `features/team/team.ts`: read-only reader of the team-hq board (`TEAM_HQ_DIR/board/`): ticket counts per column, in-progress/review/blocked tickets (id and title, max 20 each) and unticked `- [ ]` lines of `NEEDS-YOU.md`; returns `null` when the folder or its `board/` is missing, which hides the Team section; never writes
  - `features/alerts/alerts.ts`: needs-attention alerts: pure `deriveAlerts()` (waiting sessions, limit windows at or above the threshold, tickets in review; ids `session:<id>`, `usage:<key>`, `ticket:<T-id>`) and a small store of dismissed ids and the threshold (default 80) in `DATA_DIR/alerts.json`, written only on change (tmp + rename), defaults on a missing or corrupt file; dismissals are dropped once their condition is gone (usage ones are kept while `limits.source === 'none'`); `buildAlerts()` is called from `state.ts` and fills `DashboardState.alerts`; failed LAN sign-ins add a fourth kind, `signin:<address>`: `recordFailedSignin(address, tMs)` is the `onFailedLogin` hook of `createAuth` (wired in `server.ts`), keeps one in-memory record per socket address (count and last time only, never the attempted token; IPv4-mapped prefix removed; max 50 addresses, the one that failed longest ago is dropped), shown as 'Failed sign-in' with address, count and last time; dismissing deletes the record, so the next failure opens a fresh alert (these ids are never written to `alerts.json`); dismiss and threshold endpoints are `POST /api/alerts/dismiss` and `POST /api/settings/alerts`
  - `devices-logic.ts`: pure device-list helpers (`createdLabel`, `lastSeenLabel`, `sortDevices`, `cleanName`), testable with `node --test`
  - `qr.ts`: QR geometry (`qrShape(text)` -> size and one SVG path) on the bundled `qrcode-generator` (devDependency, MIT, no dependencies; Vite bundles it into the app chunk, nothing new at server runtime), testable with `node --test`
  - `features/devices/devices-panel.vue` (with `devices-status.ts`, the shared status line the QR view also writes): the Vue panel mounted into `#devices` (Devices popup), shown only when `features.manageDevices` is true (the PC) and cleared when hidden; add form (`POST /api/devices`) shows the one-time token as escaped text in `#devices-token` with Copy and Dismiss, removes it from the DOM (`v-if`) on dismiss, next add or hide, and never stores it anywhere; the list (`GET /api/devices`, fetched on show, after create/revoke and at most every 30 s) rebuilds only when changed; Revoke asks `window.confirm` first; only known fixed server error strings are shown
  - `audit.logic.ts`: pure audit-view helpers (`rowOf`, `timeLabel`, `actionLabel`, `mergeDeviceOptions`, `auditQuery`), testable with `node --test`
  - `audit-panel.vue`: Vue panel mounted into `<section id="audit">` of the Activity popup (shown to every signed-in browser): loads `GET /api/audit` only when the popup opens, on a device-filter change and on Refresh (no polling; state pushes do nothing), ignores stale responses, keeps the device choices of earlier loads so filtering does not shrink the dropdown, rows show time, device, action, project/session, ok/failed (as text) and the prompt excerpt (CSS-clipped, full text in `data-tip`); Vue escapes everything; only two known server error strings are shown
  - Device endpoints in `server.ts` (LAN mode only, 404 without a login): `GET /api/devices` (id, name, createdMs, lastSeenMs), `POST /api/devices` `{ name }` (returns `{ id, token }` once), `POST /api/devices/revoke` `{ id }` (404 `unknown device`; 500 when the removal could not be saved, after sessions and streams were already ended). Only the loopback-exempt `pc` may call them; a signed-in LAN device gets 403. `DashboardState.features.manageDevices` is true only for `pc` (per request and per event-stream client). Create and revoke are audited with device, id and name, never the token
  - `server.ts`: HTTP(S) server: Host/Origin/CSRF checks, login, `/api/state`, `/api/events` (SSE every 2s), transcript and subagent transcript endpoints, command endpoints, static files from `public/`
  - `auth/devices.ts`: device store in `DATA_DIR/devices.json` (`id`, `name`, token `sha256`, `createdMs`, `lastSeenMs`; tokens are 32 random bytes, shown once by `create(name)`, never stored); `verify()` compares hashes timing-safely against every device; `revoke(id)`; `touch(id)` keeps `lastSeenMs` in memory and writes the file at most once a minute per device; a missing or corrupt file is an empty store; max 100 devices; `create()` throws `could not save devices` (keeping nothing) when the file cannot be written, and `revoke()` returns `{ found, persisted }`
  - `features/audit-log/audit-log.ts`: reader for `GET /api/audit[?device=<id>]` (any signed-in device or the PC): the last 1 MB of `DATA_DIR/commands.log` at most (a cut first line is dropped), newest first, at most 200 entries, malformed lines skipped, only the fields `ts`, `action`, `device` (name), `deviceId` (`pc` for this PC), `project`, `session`, `mode`, `ok`, `prompt` (200 chars), never `ip`, target ids or names, or anything else; entries written before device names existed (id in `device`, or no device) still parse; errors answer a fixed string. Every `audit()` call in `server.ts` spreads the acting device (`device` name, `deviceId`; `This PC` / `pc` for the loopback exemption and for localhost mode)
  - `auth/auth.ts`: LAN sign-in with a device token (timing-safe, per-IP rate limit of 5 a minute, `onFailedLogin(ip, tMs)` hook for failed and rate-limited attempts), in-memory cookie sessions bound to a device id that slide (each authed request extends them to 7 days, never past 90 days after sign-in; at most 10 sessions per device, the oldest ends when an 11th signs in, token or QR; cookie re-issued at most once a day); every way a session can end (logout, expiry, the cap, device revoke) goes through one `endSession()` that calls the `onSessionEnd` listeners, and `sweepExpired()` (called by the 2 s event tick, since an open stream makes no requests) ends the sessions that ran out; `server.ts` keeps each `/api/events` stream with its device and session and closes it when that session ends or the device is revoked (the PC stream has no session); `identify(req)` returns the device id, or `pc` for the loopback exemption (socket `remoteAddress` loopback AND `Host` loopback; forwarding headers are never trusted, and one being present withdraws the exemption); `revokeDevice(id)` deletes the device, ends its sessions and notifies `onRevoke` listeners (`server.ts` closes that device's `/api/events` streams). The old `DATA_DIR/token` is no longer read and is deleted at startup. Anything on this PC that forwards to the dashboard (proxy, tunnel) connects from loopback: with the exemption, never expose the dashboard through one without revisiting team-hq decision 0003. Any local process or user on this PC can create a device through the loopback exemption, so local code execution here equals LAN remote execution (accepted in decision 0003). QR pairing: `POST /api/devices/pair` `{ id }` (PC only, like the other device endpoints; audited without the code) returns `{ path, urls, expiresMs }`: `path` is `/pair?c=<code>` (32 random bytes, valid 10 minutes, in memory only, spent by its first use, only the newest code per device works, max 200 outstanding) and `urls` are the same link on each LAN IPv4 address of the PC (a phone cannot use the loopback Host). `/pair` is in `PUBLIC_PATHS` (LAN mode only) and has two steps, so a camera app or link preview that fetches the URL cannot spend the code: `GET /pair?c=` has no side effect (`auth.peekPairing()`) and serves `pair.html` filled in by the server ("Sign in as <device>?", the name HTML-escaped, or an error text for an unknown, used or expired code) with the external script `pair.js`; its button sends a same-origin `POST /pair` (form body `c=`, the normal Origin check): a good code is spent and answers 200 with the device session cookie, after which `pair.js` navigates to `/` itself (a 303 ending a navigation started in another app would not carry the `SameSite=Strict` cookie), anything else answers 401 (429 when rate limited) after counting against the sign-in rate limit and calling `onFailedLogin` (so it raises the failed-sign-in alert); revoking a device drops its codes; responses are `no-store`. The QR never contains the device token. Every audit entry in `commands.log` carries `device` and `deviceId` (see `audit-log.ts`)
  - `auth/tls.ts`: self-signed cert for LAN mode via Git's `openssl`
  - `claude/claude-cli.ts`: the **only** place that runs `claude.exe` (`--bg`, `--bg --resume`, `stop`, `logs`), plus the audit log
  - `transcripts/transcript-line.ts`: the typed transcript line (`TranscriptLine`) and `parseTranscriptLine()`; fields of the wrong type are dropped, a non-object line is skipped. The scanner, viewer, aggregates and subagent index all read this type, never raw JSON
  - `transcripts/transcript-view.ts`: turns a transcript into readable entries for the viewer (last 32 MB of a file at most; `sidechain` flag for subagent transcripts)
  - `features/settings/settings.ts`: the summary mode (`recap` default | `model`) in `DATA_DIR/settings.json`, via `GET/POST /api/settings/summary`; a bad or unreadable file means `recap`.
  - `claude/session-summary.ts`: no-model recap for `GET /api/sessions/:id/summary` (times, status, token totals, last 5 tool actions, last reply cut to 300 chars; same 32 MB tail as the viewer); `summarize(path, mode, live)` is the seam for a later model mode
- `src/client/`: TypeScript and SCSS built by Vite, with Vue 3 installed and wired in for the panel migration (decision 0007: Composition API, `<script setup lang="ts">`, no Pinia, no `v-html`); today every panel is still a vanilla view; charts drawn as inline SVG
  - `app/app.ts`: shell, renders nothing itself: calls the feature views from one render step list (each step isolated, a failing step shows the render warning), keeps the latest state, mounts the tooltip component (`tooltip.vue`, host `#tip-root`), `initUsage`, popups and the other `init*` functions, and the 10 s `tickTimes` tick
  - `app/appearance.ts`: `initAppearance()`: skin picker (localStorage `skin`, applies `data-skin` to `<html>`, hides the Theme button in dark-only skins) and light/dark theme toggle (localStorage `theme`)
  - `app/state-stream.ts`: `connectStateStream(onState, onBadPush)`: the `/api/events` EventSource, the connection badge, and the `/api/state` probe on error (redirects to login on 401)
  - `app/patch.ts`: in-place DOM patcher (`patchHtml`, `patchChildren`, `patchIfChanged`, `forgetHtml`); keyed by `data-key`, skips identical markup
  - `features/limits/limits-panel.vue` / `limits.logic.ts`: the Vue panel mounted into `#limits` reads the dashboard state store (gauges, last hits, source); pure `clampPercent`, `limitLevelClass`, `limitStatusText`, `highestUtilization` (critical from 90 %, warning from 75 %)
  - `features/projects/projects-panel.vue` / `projects.logic.ts`: the Vue panel mounted into `#projects`; reads the state store and derives its cards only while the Projects popup is open (`useOpenPopup()`); cards carry `data-building`; pure `countWorkingSubagents`, `subagentsText`
  - `features/sessions/sessions-panel.vue` / `sessions.logic.ts`: the Vue panel mounted into `#sessions` (live-session table, pending requests, recent sessions); pure `isBackgroundSession`, `dotStateClass`
  - `features/messages/messages.view.ts` / `messages.logic.ts`: `renderMessages` draws the session message graph and feed in `#comms`; pure `buildMessageGraph` (circle layout, one edge per sender/receiver pair)
  - `features/usage/usage.view.ts` / `usage.logic.ts`: `renderUsage` draws the stacked 14-day token chart and tables in `#usage`; `initUsage(getLatestState)` wires the legend toggles; pure `seriesNames`, `otherTokensOfDay`, `visibleDayTotal`, `daySegments`
  - `features/tooltip/tooltip.vue`: the floating `data-tip` tooltip as a Vue component mounted on `#tip-root`, text only (mustache text, never `v-html`)
  - `app/boot.ts`: head script that applies the saved skin and theme before first paint (runs before any other JS to avoid flashing Classic when Root is chosen)
  - `features/building/building-dialog.vue`: the Vue project building dialog mounted into `#building-dialog` (renders `#building`; opens from `[data-building]` cards, title/subtitle, Close, backdrop, Esc not while the drawer is open, room/cubicle activation opens the transcript); the drawing is `building-scene.vue` (floors, sign, door; mounted once into `#building-body`, reads the store and the open project from `building-selection.ts`), `building-room.vue` / `building-empty-room.vue` (rooms), `building-annex.vue` / `building-cubicle.vue` (subagent cubicles, pipes), `building-layout.logic.ts` (pure positions and pipe paths) and `building.logic.ts` (geometry constants, tooltips, subtitle). The popup shows: rooms for each live session (worker animation by status: busy/waiting/idle, hard hat for background), annex below with cubicles for subagents (one per room, up to 24 per session); pipes show who handed work down (main → bus/stub; subagent → dashed pipe from parent); animations: envelope while working, tick when handed back; click room or cubicle to read transcript; uses `moodOf` from `features/core/mood.logic.ts` for status
  - `features/controls/controls.view.ts`: the run panel and the transcript drawer (read-write for main sessions, read-only for subagents with `kind: 'subagent'`)

The tile sections stay in the DOM inside `#popups` and keep rendering on every push (so input, focus and selection survive); open/close rules (toggle, Esc only when building/drawer are closed, backdrop click, hidden-section buttons) are pure in `popups-logic.ts`

- `vite.config.ts`: the client build. The app bundle is `assets/index-<hash>.js`. `style.scss` is linked from each page and written as `style.css`. `boot.js` (loaded as a classic script from `<head>` so the skin applies before first paint) and `pair.js` (the Vue pair form of `features/pair/`, a classic script at the end of `pair.html`) are separate IIFE builds with no imports, run from plugin hooks: the server serves only `/pair.js` before login, so `pair.js` cannot share the hashed `assets/` chunks. ## Data sources (format of Claude Code's internal files, not a public API)

- `~/.claude/sessions/<pid>.json`: one file per session (`kind`, `status`, `name`, `cwd`). A session counts as live only if its `pid` is still running.
  - Whether `status` becomes `waiting` on a permission prompt: not checked (no live session file was available to inspect).
- `~/.claude/projects/<slug>/<sessionId>.jsonl`: transcripts. The slug is the cwd with every non-alphanumeric character replaced by `-`. Subagent transcripts live in `<sessionId>/subagents/agent-<id>.jsonl` (one per Agent tool call) plus `.meta.json` with `agentType`, `description`, `toolUseId` (links to spawner's Agent tool_use id), and request shape. All subagent transcripts are filtered by `isSidechain` and included in `DashboardState.subagents`.
- Token usage comes from `message.usage` on assistant lines, deduplicated by `message.id` + `requestId`. `<synthetic>` models are skipped.
- Incoming messages have `origin.kind === "peer"`. Subagent hand-backs appear both ways: (1) tool_result with `status === "completed"` when the spawner reads the Agent tool result; (2) peer origin with `senderTaskId` on user lines (body starts with `[Subagent hand-back]`, older form). Outgoing messages are `SendMessage` tool_use blocks. Subagent hand-backs both confirmed.
- Session-to-session messages (confirmed 2026-10-08, Claude Code 2.1.295, from a headless `claude -p -n probe-T-003` run messaging a named session):
  - Incoming: an `attachment` line with `attachment.type === "queued_command"`, `attachment.prompt` = `<cross-session-message from="…" from-name="…" from-mode="…">body</cross-session-message>`, and `attachment.origin = { kind: "peer", from, msg_id, name, fromMode, body }`. `name` is the sender's session name; `from` is its local pipe address (`uds:\\.\pipe\LOCAL\cc-msg-<hex>`), useless for display. There is no `senderTaskId`, which is what tells it apart from a subagent hand-back. A `queue-operation` line with the same text is also written; it is ignored.
  - Outgoing: `SendMessage` tool_use with `input = { to, message, summary?, type: "message", recipient, recipient_kind: "name", content }`. `to` is the target name, optionally with a ListAgents ref (`"worker [3fa9c1]"`), which is stripped. A failed send (`toolUseResult.success === false`, e.g. "No agent named 'lead' is reachable") still has the tool_use and is still listed.
- Rate-limit hits are lines with `quotaLimits.status === "rejected"`.
- `~/.claude.json` → `cachedUsageUtilization` is the fallback for limits; `projects[...].hasTrustDialogAccepted` is the CLI trust flag per folder.

## Environment variables

- `DASHBOARD_PORT` (4777), `DASHBOARD_HOST` (`127.0.0.1`; anything else means LAN mode)
- `DASHBOARD_COMMANDS` (`0` removes all command endpoints)
- `DASHBOARD_LIVE_USAGE` (polling on by default; `0` turns it off)
- `DASHBOARD_DATA_DIR` (`./.dashboard`)
- `TEAM_HQ_DIR` (`N:\team-hq`): team-hq board folder read by `team.ts` (read-only); the Team section is hidden if `board/` is missing
- `PROJECTS_ROOT` (`N:\Projects`), `CLAUDE_DIR` (`$CLAUDE_CONFIG_DIR`, else `~/.claude`), `CLAUDE_JSON` (`$CLAUDE_CONFIG_DIR/.claude.json`, else `~/.claude.json`); Claude Code relocates both when `CLAUDE_CONFIG_DIR` is set, as on this PC (`N:\ClaudeData\config`)
- `CLAUDE_BIN` (default: the CLI found in this order: `claude.exe` in a `PATH` folder, then the newest `claude.exe` in `~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/`), `CLAUDE_BIN_ARGS` (JSON array prefix, used by tests), `OPENSSL`

## Claude CLI behaviour (verified)

- Binary lookup order: `CLAUDE_BIN` (+ `CLAUDE_BIN_ARGS`); `claude.exe` (`claude` off Windows) in an absolute `PATH` folder (on Windows only drive-letter paths, no drive-less or UNC entries), native binaries only since `execFile` can't run `.cmd` shims; newest `claude.exe` in the VS Code extension. None found: "Claude CLI not found (set CLAUDE_BIN)". On this PC: `C:\Users\Chris\.local\bin\claude.exe` (2.1.295, found via `PATH`).
- The CLI refuses folders it doesn't trust ("Workspace not trusted"). Trust is only granted by running `claude` interactively in that folder once. The dashboard shows trust status and passes the refusal through as `needsTrust`. Never edit `.claude.json` to grant trust.
- **Model summaries** (`summarizeWithModel()` in `claude-cli.ts`, only when the setting is `model`): `claude -p <fixed instruction> --model haiku --tools "" --disable-slash-commands --strict-mcp-config --setting-sources user --no-session-persistence --output-format text`, run in the projects root. `--tools ""` disables all tools (verified in `claude --help` of 2.1.295: "Use "" to disable all tools"). The transcript excerpt (newest user/assistant text, secrets masked, max 20 KB) goes in on **stdin** as data, never in the argument list. Same 60 s timeout and 4-process cap as other commands; audited as `action: 'summary'` (session, device, ok; no text). Any failure returns the recap with `mode: 'recap'` and a fixed `note`. Answers are cached in memory only (answer text, never transcript text; max 50 sessions, oldest dropped) and reused while the transcript size/mtime is unchanged; a new call for the same session waits 60 s (inside it: the cached answer, or the recap with a fixed note). With commands disabled the endpoint always answers `recap` and the settings panel shows a fixed note.
- `claude agents --json` lists the same live sessions as `~/.claude/sessions/*.json`.
- **Unverified until a folder is trusted:**
  - the exact `--bg` output and id format (`toResult()` parses a UUID or a lone id line);
  - how a background session behaves when it hits a permission prompt.

## Tests

- `tests/helpers.ts` → `makeFixture()` builds a fake `~/.claude`, projects tree and data dir in a temp dir and sets the env vars above. Server modules read env when they load, so call `makeFixture()` **before** a dynamic `await import(...)` of the module under test.
- Component tests (`*.component.spec.ts`, Vitest + `happy-dom`) are run by `npm run test:component`; `node --test` only matches `*.test.ts`.
- `node --test` runs each file in its own process, so module-level state doesn't leak between files.
- Inside one file, `resetTranscripts()` also forgets file offsets, so the next scan re-reads every fixture written so far. Filter assertions by `sessionId`.
- Mock `globalThis.fetch` in tests; tests must never touch the network or real user files.
- Command tests use `tests/fake-claude.mjs` via `CLAUDE_BIN=node` + `CLAUDE_BIN_ARGS`. It records argv and cwd to `FAKE_CLAUDE_LOG`. Assert exact argument arrays.
- Use `raw()` from `helpers.ts` for HTTP tests that must set `Host`, `Origin` or cookies exactly (`fetch` normalises these).
- Test files: `tests/client/features/core/mood.logic.test.ts` (session/subagent mood logic), `tests/client/skins/skin.test.ts` (skin parsing), `tests/server/static-fonts.test.ts` (font file validation), `tests/client/skins/root-assets.test.ts` (Root skin SVG guard), `tests/copy-assets.test.ts` (asset copying), `tests/server/claude/claude-bin.test.ts` (Claude CLI lookup order), `tests/server/features/team/team.test.ts` (team-hq board reader, `DashboardState.team`), `tests/server/features/alerts/alerts.test.ts` (alert derivation and dismissal store), `tests/client/features/alerts/alerts.logic.test.ts` (client new-alert detection and badge count), `tests/client/features/chat/chat.logic.test.ts` (chat intents and replies), `tests/client/features/chat/chat-state.logic.test.ts` (chat history and pending confirm), `tests/client/features/chat/chat.view.test.ts` (source scan: the chat only calls the message and dismiss endpoints), `tests/server/auth/devices.test.ts` (device store), `tests/client/features/devices/devices.logic.test.ts` (client device-list helpers), `tests/client/features/devices/qr.logic.test.ts` (QR geometry), `tests/server/features/audit-log/audit-log.test.ts` (audit reader), `tests/client/features/audit/audit.logic.test.ts` (client audit-view helpers), `tests/server/auth/auth.test.ts` (sign-in, sliding sessions and their 90-day limit and 10-session cap, session-end listeners, revocation, loopback exemption); device endpoints are covered in `tests/server/lan.test.ts` and `tests/server/server.test.ts`.

## UI conventions

- Colors use the validated palette from the `dataviz` skill, defined once in `style.scss` with light and dark versions. Dark mode follows the OS and can be overridden with `data-theme` on `<html>`.
- **Skins:** CSS themes swap tokens (`--font-ui`, `--font-mono`, `--accent`, `--radius-panel`, etc.) and must keep the validated chart series `--s1..--s8` (for accessibility). Classic (light/dark, OS-following, system fonts); Co-pilot (dark only, KITT-inspired); Root (deep blue, glowing tree, Cormorant Garamond italic + Nunito Sans). New skins: add `skins/_<name>.scss` with one `meta.load-css` line, extend `Skin`/`SKINS` types, add an `<option>` to the selector. Skin artwork is static same-origin SVG under `src/client/skins/<name>/`, served as `<img>`, never inlined via innerHTML; any SVG must pass `checkSvg` (whole-file tokenizer, allowlisted elements/attributes, printable ASCII only, no external refs, local `url(#id)` only). The build enforces this: `copy-assets.mjs` fails if an SVG fails the check.
- Heavy scene DOM is built lazily only for its skin (e.g., `ensureRootScene()` in `root-scene.ts` only when Root is active), so other skins never load unused artwork.
- Fonts must be self-hosted under `/fonts/` (files + OFL licence .txt); the CSP (`default-src 'self'`) blocks Google Fonts. Never relax the CSP for fonts.
- Section renders go through `patchHtml(el, html)` (`patch.ts`): the new markup is diffed against the live DOM, so unchanged nodes are never touched (focus, selection, scroll, CSS animations survive). Give list rows a `data-key` so they keep their node on reorder. Relative times are emitted with `timeSpan()` (`shared/escape.ts`) and advanced by a 10 s `tickTimes()` that only rewrites changed text. For one-off animated elements (core strip) still build once and patch by hand.
- **In-place update and popups:** each state push renders every section with `patchHtml`, never by replacing `innerHTML`, so focus, selection, scroll and animations stay. `patchHtml` remembers the last markup per element and skips the DOM walk when the string is unchanged. The tile sections live inside `#popups` and are patched on a push only while their popup is open; opening a popup first draws its section from the latest state (`drawPopup` in `app.ts`, open/close rules in `popups-logic.ts`). This keeps idle CPU low (numbers in `docs/perf.md`).
- Animations always run: don't add `prefers-reduced-motion` rules (the user chose this; Windows "Animation effects" is off on this PC, which made browsers freeze every animation).
- Animate only transform and opacity; filters only on static layers (the dashboard runs all day).
- Project colors are assigned by project name in alphabetical order, never by rank. A filter must not recolor the projects that stay visible.
- **No inline styles in new client code:** sizes, colours, animation delays are defined as CSS classes in `style.scss` (e.g. `.tint-N`, `.shirt-N`, `.skin-N`, `.building__svg--cols-N`). Existing inline styles (chart bars, legend swatch in `app.ts`) pre-date this rule and are not changed.
- Escape every interpolated string with `esc()` (`shared/escape.ts`), since rendering uses `innerHTML`.
- Forms (run panel, follow-up box) are never re-rendered by state pushes, so typing isn't interrupted; `updateControls()` only patches options.
